## What runs in the simulator

1. The host loads `GRIDLegends.dylib` and calls its entry; `NSApplicationMain` makes `CFeralNSApplication` the shared
   application **and its own delegate** (the connection MainMenu.nib makes on a Mac; without it nothing starts).
2. **The game thread must be the main thread**: Feral checks `pthread_main_np()` and otherwise waits for work it queued
   for the main thread. libglsystem answers 1 on the game thread and libglcf's `CFRunLoopGetMain` returns the game
   thread's run loop (VXpro's model: the program thread stands in for the Mac's main thread).
3. The bundle redirect works (`CFBundleGetMainBundle`, `+[NSBundle mainBundle]` → `Documents/GRIDLegends.app`); the game
   creates its `VFS`, `cache`, `Documents` folders; the seeded settings skip the pre-game launcher.
4. About 3 s in, **the game ends itself with `_Exit(173)`** from Feral's activation response handler:

```
_Exit(173)
GRIDLegends.dylib+0xc099c0   NFunctionView<bool(const FeralVFS_VFile_t*)>::do_fn_call
GRIDLegends.dylib+0x13b4108  ... CActivationResponse ...   (from a delayed perform on the game's run loop)
```

## The activation check (correction to Phase 0)

Phase 0 concluded the receipt does not block start-up. That was incomplete. Feral's games carry their own
**online activation** (`CActivation`, `CActivationRequest`/`CActivationResponse`, strings `<licence-id>`,
`Activation.ComputerDeauthorisedByDownload`, `Activation.ComputerBlacklisted`, `Activation.AppStoreConnectionFailure`...).
When it fails, the game exits with 173, the Mac App Store's "no valid receipt" code.

On the Mac test it passed. The likely reason (not verified): the test copy ran as you, outside the sandbox, so it could
read your real installation's activation record (the game imports the legacy keychain calls
`SecKeychainFindGenericPassword`/`AddGenericPassword`). On visionOS none of that exists: no keychain item, no
receipt in the host app, a different device, and DeviceCheck/App Attest tied to a different app and team.

The plan does not include patching out or spoofing license checks (for example faking the Mac's hardware identity or
copying an activation record to pass the check).

### Result with your own receipt (decided 2026-11-23)

Your App Store receipt, copied unchanged from `/Applications/GRIDLegends.app/Contents/_MASReceipt/receipt` to the
redirected bundle's `Contents/_MASReceipt/receipt` (tools/sim_run.sh; GL_NO_RECEIPT=1 leaves it out), is enough. A/B in
the simulator with the same build:

| | Result |
|---|---|
| No receipt | `_Exit(173)` after ~2 s (activation response handler) |
| Your receipt | activation passes; the game creates its 1600x900 `CFeralNSWindow`, its Metal view, loads shader archives |

The game never asked for `appStoreReceiptURL` (logged by libglfoundation): it reads the receipt from its bundle's
`Contents/_MASReceipt/receipt` itself. Whether Feral's server was contacted for this is not known (the traffic is TLS).
On the headset the same file must be copied with the game's data (`tools/vxmac_grid.py copy`, Phase 2).

## After activation: fixed on the way

- `-[NSView setSubviews:]` (libglkit): Feral's views set their children with it and read `subviews[0]` back (an
  uncaught NSRangeException otherwise).
- `MTLStorageModeManaged` (libglmtl): visionOS's Metal refuses it; textures become Shared (depth/stencil Private),
  buffers Shared. On Apple silicon a managed resource is one shared copy anyway; libvxmtl already makes
  `didModifyRange:` / `synchronizeResource:` no-ops.

## Where the simulator stops

`-[MTLSimBuffer newTextureWithDescriptor:offset:bytesPerRow:]: Linear texture can only be created on buffers with
MTLStorageModePrivate in the simulator`. This restriction is the simulator's (VXpro's Cyberpunk run also ended at
simulator Metal limits); the headset's GPU allows linear textures on shared buffers. Next: Phase 2 on the headset.

Also seen: the game reserves **16 GB** at `0x7000000000` (`GRIDLegends.dylib+0x1145c20`, logged by libvxsystem). Phase 0
attributed that region to WebKit; it is the game's own. With Extended Virtual Addressing that should be fine (Cyberpunk's
failure was a 64 GB reservation); to be confirmed on the headset.
